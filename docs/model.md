# Класова модель ShopOrders (ЛР4)

**Варіант:** №1 — облік замовлень інтернет-магазину.

## 1. Таблиця сутностей

| Роль | Тип | Незмінність | Головний інваріант |
|------|-----|-------------|-------------------|
| Документ (агрегат) | `Order` | колекція рядків інкапсульована | `Id > 0`; рядки змінюються лише у `New` |
| Позиція | `OrderLine` | після ctor | `Quantity > 0`, ціна ≥ 0 |
| Клієнт | `Customer` | після ctor | непорожнє ім’я; email містить `@` |
| Гроші | `Money` | value object | `Amount ≥ 0` (від’ємні відхиляються) |
| Знижка | `Discount` | value object | частка в допустимому діапазоні |
| Політика знижки | `IDiscountPolicy` | інтерфейс | реалізація не змінює агрегат напряму |
| Сховище | `IOrderRepository` | інтерфейс | DIP для Application |

## 2. Стани документа та переходи

| З \ На | New | Confirmed | Shipped | Cancelled |
|--------|-----|-----------|---------|-----------|
| New | — | `Confirm()` (≥1 рядок) | заборонено | `Cancel()` |
| Confirmed | заборонено | — | `Ship()` | `Cancel()` |
| Shipped | заборонено | заборонено | — | заборонено |
| Cancelled | заборонено | заборонено | заборонено | — |

Примітка: у методичці для варіанта 1 наведено приклад із `Paid`/`Returned`. У реалізації ShopOrders використано `Confirmed` як стан після підтвердження оплати/замовлення; `Returned` не моделюється окремим переходом у поточній версії (зафіксовано як техборг у `docs/tech-debt.md`).

## 3. Було → стало (інкапсуляція)

| Було | Стало | Навіщо |
|------|-------|--------|
| Публічний список рядків | `IReadOnlyList<OrderLine> Lines` + `AddLine` | захист інваріанту стану |
| Літерали `0.2` / `0.05` | `FinancialConstants` | відсутність magic numbers |
| Знижка всередині сервісу | `IDiscountPolicy` | OCP / DIP |
