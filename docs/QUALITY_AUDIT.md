# Аудит якості та рефакторинг (SR2)

**Проєкт:** ShopOrders  
**Виконавець:** студент групи (варіант 1)

## 1. Контекст «до»

На старті (як типовий «успадкований» фрагмент лабораторій) розрахунок підсумку замовлення був зосереджений в одному «монстр-методі»: підсумовування рядків, знижка, ПДВ, друк і валідація впереміш; ставки як літерали `0.2` / `0.05`; можливе використання `double`.

## 2. Метрики (оціночні LOC / складність)

| Метрика | До (оцінка) | Після | Коментар |
|---------|-------------|-------|----------|
| LOC методу розрахунку підсумку | ~45–60 | `CalculateTotals` ≈ 12 + 2 приватні ≈ 10 | декомпозиція LR3 |
| Цикломатична складність (CC) розрахунку | ~8–10 | 1–2 на метод | гілки винесені |
| Magic numbers у фінансовій логіці | 4+ | 0 | `FinancialConstants` |
| Публічні доменні типи з інваріантами | 0–1 | ≥4 | Order, OrderLine, Customer, Money/Discount |
| Попередження аналізаторів | N/A | 0 | TreatWarningsAsErrors |
| Тести ключової логіки | 0 | ≥10 фактів/теорій | LR7 |

*LOC підраховано вручну по файлах `Order.cs` / сервісу; для звіту DOCX можна вставити скрін `dotnet build` / IDE metrics.*

## 3. Що змінено

1. **Extract Method:** `SumLineTotals`, `CalculateVat`.
2. **Introduce Named Constant:** VAT, пороги знижки.
3. **Replace Primitive:** `Money`, `Discount`.
4. **Encapsulate Collection:** `IReadOnlyList<OrderLine>`.
5. **Dependency Inversion:** `IDiscountPolicy`, `IOrderRepository`.
6. **Result + logging:** `OrderService` без тихого fail.
7. **Smell cleanup:** див. `SMELLS_LAB06.md`.

Після рефакторингу фінансова логіка перевіряється тестами, збирається без попереджень і відповідає стандарту `docs/CODING_STANDARD.md`.
